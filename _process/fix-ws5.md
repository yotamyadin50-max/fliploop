## How the policy was tested (PWA-P3)

With the exact `Content-Security-Policy` header from `_headers` sent by a local server (port 9445) and the same policy as a `<meta>` in the page, both active at once: GIF (full, half, 256 colours), video (8 first exports plus 7 more cases), PDF A4 and Letter, PNG sheets, print, project file download, import, Google Fonts, the service worker (install, offline, 404 page), `selfTest({ count: 12 })`. `securitypolicyviolation` events collected in every run: **0**. Under the subpath server the `<meta>` alone gave the same result.

**One thing the integrator must know:** Playwright's `page.waitForFunction()` evaluates a string inside the page, and the policy (no `'unsafe-eval'`) refuses it with an `EvalError`. `page.evaluate()` and locators still work. After the merge, every regression script that calls `waitForFunction` needs either `bypassCSP: true` in `newContext()` (then that run does not test the policy) or a polling helper built on `page.evaluate()` (`until()` in `pw2/fix-ws5/h.mjs`). This is the policy doing its job, not an app defect.
