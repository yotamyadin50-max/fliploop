# Fix round WS6: layout, visual drift, accessibility markup, navigation, UI copy

**Role:** Developer · **Branch:** `fix/ws6` · **Worktree:** `.worktrees/ws6` · **Server:** `http://127.0.0.1:9406` (from `site/`) · **Dates:** 2026-10-01 and 2026-10-02
**Binding file:** `_process/12-fix-direction.md` (sections 0, 1, 2, 3, 5, 6, WS6 in 7, 8).
**Scripts and screenshots (scratch, not project files):** `scratchpad/pw2/fix-ws6/` (`lib.mjs`, `r01` ... scripts, `shots/before-*.png` and `shots/after-*.png`).
**Method:** real Chrome through Playwright (`channel: "chrome"`, headless), `serviceWorkers: "block"`, `locale: "he-IL"`, real mouse and keyboard input, a fresh context per scenario. Each item was reproduced on the untouched branch first (`TAG=before`), then re-run after the fix (`TAG=after`). WebKit runs are named where they were done.

**One test artefact, said once:** with service workers blocked, Playwright makes `navigator.serviceWorker.register()` resolve to `undefined`, and the frozen `js/pwa.js` then throws `Cannot read properties of undefined (reading 'waiting')` once per page load. It is on the untouched base as well (measured: same count per page load on port 9416), so it is not caused by any WS6 change. From reading `pwa.js` it should not happen when a real worker registers, but that was not run here (rule 1.6 has every WS6 test run with workers blocked). Every "0 console errors" below counts all other errors; this one is listed under "noticed outside my area".

**One mistake of my own tooling, so nobody repeats it:** a first page load timed out three times during the work. Each time, two of my scripts were using the one single-threaded `python -m http.server` at once; no script run alone ever failed. I first blamed the Google Fonts stylesheet, without checking; when checked, that host answered in 0.2 s. All final numbers below come from scripts run one at a time.
