### What's genuinely working
- **The first Play is a real signature moment and it lands.** Seen mid-run at 375: the tools dim to 40%, the onion fades out, the canvas picks up an amber glow, the Lamp gate over the centre cell reads "2/4", the cells outside it dim, and "הציור שלכם הפך לסרט." appears above the gate. Stop hands the showing frame back as current. This is exactly the Concept ("pressing Play threads that film through a lamp-lit projector gate"), and it beats FlipaClip's plain loop. Keep it as it is.
- **The coach sequence teaches by doing.** "ציירו משהו", then "הוסיפו פריים וציירו הלאה" only after the first stroke, then "עכשיו לחצו על הפעלה" only once a second frame exists. Each tip waits for the action before it, so a first-timer is never told about something they cannot do yet.
- **The onion reads correctly on real drawings.** The previous frame showed red and the next frame blue, faint and under the ink, on my own circles. After Stop on frame 1, the blue ghost of frame 2 sat exactly where the next pose goes. That is the whole point of the feature, and it works on a child's first try.
- **The lesson loop pays off.** Filling 6/6 plus Play gave the stamp sheet and put a "כדור" starter into Gallery. Trying to draw on a locked key frame gave a clear, specific toast instead of a silent refusal.
- **The keyboard path is complete and in the right order**, with a 3px ring on light surfaces and a Lamp ring on the film.

### Quick wins vs. bigger bets
- **Quick wins (small, contained):** F1 is one place: sheets close when the route changes (it lives in `dialog.js` and the router). F2 is a type-token decision at `--font-display` for Hebrew, with the Latin wordmark free to stay. F5, F6, F7, F8 and F9 are single-line changes.
- **A bigger bet:** F3 needs a small design decision (where the steps live inside the Editor without crowding the 343px canvas), so Web Designer should own it, not Developer alone.
- **Routing suggestion for Build Manager:** F1 → Developer. F2 → Web Designer (it is the approved type choice, so the call is theirs; the Latin/Hebrew split may be the answer). F3 → Web Designer for placement, then Developer.

### For the loop
- A hash-routed SPA that opens native `<dialog>` sheets on `body` has to close them on every route change. Otherwise browser Back strands a live sheet over another screen, and its actions still change data (seen here as a real frame erased). This is generalizable to every Track B app the system builds.
- A Hebrew "handwritten" display font can be cursive script (כתב), not handwritten print. The Web Designer's font check should render real Hebrew words and confirm print letterforms whenever the audience includes early readers. Checking that glyphs are present, the current spot check, does not catch this.
